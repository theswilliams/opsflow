# n8n integration

OpsFlow exposes a small, signed HTTP API so an orchestrator such as n8n can hand it work and wait for the human decision.

```text
n8n Webhook / Email trigger
   → Sign request (Code)
   → POST /api/webhooks/workflow        OpsFlow: AI extraction → validation → REVIEW_REQUIRED
   → Wait (30 s)
   → Sign status request (Code)
   → GET  /api/webhooks/workflow/:id     … a person reviews and approves in OpsFlow …
   → Switch on status
        COMPLETED → notify with `confirmation`
        REJECTED  → notify rejected
        FAILED    → alert with `failure_reason`
        (other)   → back to Wait
```

## 1. Create a credential

In OpsFlow open **Integrations → Webhook credentials → Create credential**. Copy the **Key ID** and **secret** — the secret is shown once and stored encrypted. (`npm run db:seed` also prints a demo credential.)

## 2. Configure n8n

Set these environment variables for n8n (never paste the secret into a node):

| Variable | Value |
| --- | --- |
| `OPSFLOW_URL` | e.g. `http://localhost:3000` (no trailing slash) |
| `OPSFLOW_KEY_ID` | `ofk_…` |
| `OPSFLOW_SECRET` | `ofs_…` |
| `NODE_FUNCTION_ALLOW_BUILTIN` | `crypto` (the Code nodes use Node's `crypto`) |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE` | `false` (allows `$env` in nodes) |

Import [`n8n/opsflow-workflow.json`](../n8n/opsflow-workflow.json) (Workflows → Import from file). Replace the three placeholder notification nodes with Slack/Email/SMS. To test end-to-end, POST to the n8n webhook `/webhook/opsflow-intake` with `{"text": "Customer: ABC…"}`, then open the workflow in OpsFlow and approve it.

> The importable JSON is generated by `scripts/build-n8n-workflow.mjs`. It has been validated structurally and its signing code is executed in the test-suite against the real handler (`tests/n8n-workflow.test.ts`), but it has **not** been imported into a running n8n instance. Node parameter formats can differ between n8n versions; if an import complains, the two Code nodes and the request headers below are the parts that matter.

## 3. The API

### Signing

Every request carries:

| Header | Value |
| --- | --- |
| `X-OpsFlow-Key-Id` | your key id |
| `X-OpsFlow-Timestamp` | Unix time in seconds |
| `X-OpsFlow-Signature` | `sha256=` + hex `HMAC-SHA256(secret, "<timestamp>.<raw body>")` |

The signature is over the **exact bytes** sent, so send the same string you signed (in n8n: HTTP Request → Body Content Type *Raw*, `application/json`, body from the Code node). For `GET`, sign an empty body: `"<timestamp>."`. Timestamps more than 5 minutes off are rejected.

```bash
BODY='{"type":"delivery_request","text":"Customer: ABC\n4 pallets of shingles to 125 King Street, London, Ontario this Friday","external_id":"order-1042"}'
TS=$(date +%s)
SIG=$(printf '%s' "$TS.$BODY" | openssl dgst -sha256 -hmac "$OPSFLOW_SECRET" | sed 's/^.* //')
curl -X POST "$OPSFLOW_URL/api/webhooks/workflow" \
  -H "Content-Type: application/json" \
  -H "X-OpsFlow-Key-Id: $OPSFLOW_KEY_ID" -H "X-OpsFlow-Timestamp: $TS" -H "X-OpsFlow-Signature: sha256=$SIG" \
  -d "$BODY"
```

Or use the helper: `OPSFLOW_KEY_ID=… OPSFLOW_SECRET=… node scripts/send-webhook.mjs http://localhost:3000`.

### `POST /api/webhooks/workflow`

Body (strict — unknown fields are rejected):

```json
{ "type": "delivery_request", "text": "…up to 20,000 chars…", "external_id": "order-1042" }
```

Optional `Idempotency-Key` header (same character rules as `external_id`: `[A-Za-z0-9_.:@-]{1,200}`). With neither, the request signature is used, so an exact replay is harmless.

Success — `201` (new) or `200` (`duplicate: true`, same workflow returned):

```json
{
  "id": "cmu…",
  "status": "REVIEW_REQUIRED",
  "needs_attention": true,
  "duplicate": false,
  "failure_reason": null,
  "review_url": "http://localhost:3000/workflows/cmu…"
}
```

`status` is `FAILED` (with a generic `failure_reason`) if extraction failed — the workflow exists and can be retried in the UI. Processing is synchronous, so allow up to ~60 s with a real model.

### `GET /api/webhooks/workflow/:id`

```json
{
  "id": "cmu…", "status": "COMPLETED", "needs_attention": false, "decision": "approved",
  "failure_reason": null, "updated_at": "2026-09-25T10:02:23.000Z",
  "data": { "customer": "…", "address": "…", "requested_date": "2026-10-02", "…": "…" },
  "confirmation": { "subject": "…", "body": "…" }
}
```

`data` (the reviewed fields) is `null` until a person has approved; `confirmation` is set after the action succeeded. A workflow that belongs to another account is `404`.

### Errors

| Status | `error.code` | Meaning |
| --- | --- | --- |
| 400 | `invalid_json` / `invalid_payload` / `invalid_idempotency_key` | Malformed body; `issues[]` lists field paths |
| 401 | `unauthorized` | Missing/unknown key, bad signature or stale timestamp (deliberately indistinguishable) |
| 404 | `not_found` | Unknown id, or not yours |
| 409 | `idempotency_conflict` | Key reused with a different payload |
| 413 | `payload_too_large` | Body over 64 KiB |
| 415 | `unsupported_media_type` | Not `application/json` |
| 429 | `rate_limited` | Honour `Retry-After` |
| 500/503 | `internal_error` / `service_unavailable` | Generic; quote the `x-request-id` header |

Limits: 64 KiB body, 60 requests/min per key, 120/min per IP, 10 failed signatures/min per (key, IP).

## Design notes

- **Polling instead of callbacks.** Accepting a callback URL would create an SSRF surface. Polling a signed `GET` needs no outbound requests from OpsFlow.
- **Approval stays in OpsFlow.** n8n can never approve; it only observes the decision. The reviewed `data` is released only after approval.
- **Loop guard.** The workflow's `executionTimeout` is 48 h; add a max-iterations counter if you need a tighter bound.
